01 / LOW-POWER SYSTEMS

Embedded E-Ink Dashboard

A low-power personal dashboard that displays my daily calendar events, weather, and prayer times onto an E-Ink display.

I developed the dashboard using an ESP32 and 3.97-inch Waveshare e-paper display, integrating Google Calendar, weather, and prayer APIs into a custom designed interface. The system retrieves and processes data during each refresh before entering deep sleep. As the interface grew, I optimized memory usage and used 1-bit graphics with dynamic text wrapping and truncation to work within the ESP32's memory constraints.

Full project details

Embedded E-Ink Dashboard

  • ESP32 connected to a 3.97-inch e-paper display over SPI, with calendar, weather, and prayer-time data retrieved during each refresh cycle.
  • Google Calendar access authenticated through OAuth 2.0, with nested JSON responses parsed into the data required by the interface.
  • A custom 1-bit framebuffer composes the full interface before each E-Ink refresh, with pixel-width calculations handling dynamic text wrapping and truncation.
  • The refresh cycle ends in deep sleep, reducing unnecessary operation while the E-Ink display retains the latest screen.
  • Memory usage was managed around simultaneous API responses, graphics buffers, and temporary data as the interface grew.

02 / SENSING + VISUALIZATION

3D Mapping System

An embedded scanning system that collects spatial measurements and reconstructs the surrounding environment as a 3D point cloud.

I developed the system using an MSP432 microcontroller, VL53L1X Time-of-Flight sensor, and stepper motor. The microcontroller coordinates 360° scans through fixed angular increments and transmits the measurements over UART. The scan data is processed in Python, converting it into 3D Cartesian coordinates, then uses Open3D to visualize the reconstructed environment. Across multiple scanning positions, the completed system collected approximately 900 measurements of a hallway.

MSP432CI²CUARTToFPythonOpen3D
Full project details

LiDAR 3D Mapping System

  • MSP-EXP432E401Y coordinates the VL53L1X Time-of-Flight sensor over I²C and controls the stepper motor throughout each 360° scan.
  • Each rotation collects 32 radial distance measurements at 11.25° intervals, followed by a counter-rotation to return the sensor assembly to its starting position.
  • Measurement data is transmitted to the computer over UART at 115200 baud and combined across multiple hallway scanning positions.
  • Python converts the radial measurements and scan positions into Cartesian coordinates for reconstruction in Open3D.
  • Approximately 900 measurements were assembled into the final point-cloud and line visualization of the scanned hallway.

03 / AUTONOMOUS ROBOTICS

McMaster SumoBot

An autonomous SumoBot designed to detect an opponent, respond to its surroundings, and remain inside the competition ring.

As part of the McMaster SumoBot Competition, I worked in a team on Shredded Bot, an Arduino Nano-based robot which uses ultrasonic sensing for opponent detection and infrared sensors for boundary detection. Its autonomous behaviour was built off a finite state machine which controls the search, attack, and defensive responses. Testing exposed unreliable boundary detections, which we addressed through software filtering and iterative hardware testing. The mechanical design was also adapted after a 3D-printing discrepancy caused the original assembly to exceed competition dimensions.

McMaster SumoBot

  • Autonomous behaviour is organized as a finite state machine with search, attack, and defend states.
  • Ultrasonic sensing provides opponent detection while infrared sensors monitor the ring boundary and influence state transitions and motor response.
  • False boundary detections encountered during testing were reduced through software filtering and repeated hardware validation.
  • A discrepancy in the 3D-printed structure caused the original assembly to exceed competition dimensions, requiring the mechanical layout to be adapted.
  • Firmware and hardware were tested iteratively to improve sensor reliability and autonomous behaviour.

04 / SOFTWARE DESIGN

Snake Game

A terminal-based Snake game developed around modular C++ classes, finite-state movement, and dynamic memory management.

The game was developed using an object-oriented architecture that separates player movement, food generation, position storage, and overall game state into individual components. I implemented finite-state movement, coordinate-based collision detection, dynamic snake growth, and constrained food generation. The project also required manual memory management for dynamically allocated game objects, with Dr. Memory used to identify memory issues and verify proper cleanup.

C++OOPFSMDynamic MemoryDr. Memory
Full project details

Snake Game

  • C++ classes separate player behaviour, food generation, position storage, and overall game state, with composition connecting the components.
  • Finite-state movement logic handles directional transitions and prevents invalid reversals during gameplay.
  • The snake is represented through dynamically managed coordinate positions, supporting growth, self-collision detection, and occupied-position checks.
  • Food-generation logic prevents items from spawning on the snake and supports different effects on score and length.
  • Dynamic allocation, ownership, and cleanup are handled explicitly through constructors and destructors, with Dr. Memory used to verify memory behaviour.
